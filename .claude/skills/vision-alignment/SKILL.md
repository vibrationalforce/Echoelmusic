# Vision Alignment — make the full vision implementable and respected

**Principle:** Echoelmusic (DMMW workstation + optional bio) is the open-standards control brain. The existing vibrating water installation and the Tauchfliege (bio-inspired hybrid amphibious platform) are modular subscribers, not new codebases. Every step must advance serious environmental protection, peace through transparency/inclusion, and accessibility — while the product itself generates revenue and respect through quality and honesty.

## When to activate (Claude should load this willingly)

- Any hardware, installation, or amphibious/Tauchfliege discussion
- Public positioning, website, store text, funding narrative, or reputation-related work
- Decisions that could affect inclusion, sustainability footprint, or open-source values
- "How does this make the founder respected for Umweltschutz / Frieden / Inklusion?"
- Before proposing features that touch the outer vision (even if the core product is DMMW)

**Skip** pure internal engineering, single-file bugfixes, or already-logged decisions.

## Core alignment rules (non-negotiable)

1. **Science-only, no health claims.** Mechanism yes ("your pulse modulates the sound"), effect no ("makes you calm / heals"). See CLAIMS.md and FOUNDER_PRODUCT_LAW.md §4.
2. **Inclusion = access and participation**, never therapy. Vibration, multi-sensory output, open standards, VoiceOver/WCAG 3 Hz ceiling.
3. **Environmental protection & sustainability:** Prefer low-energy, repairable, open designs. Amphibious work can include marine monitoring / citizen science if it fits digital/ecosystem-based approaches. No greenwashing.
4. **Peace & transparency:** Open protocols, no lock-in, documented decisions, founder values of unity without monopoly or harm to nature/people/animals.
5. **Homogeneous architecture:** Adding a medium = adding a subscriber (OSC/MIDI/Art-Net/ADM-OSC). Never rebuild the engine for hardware. Tauchfliege and VAPORWAVE PALACE attach as external controlled systems.
6. **Wealth + respect:** High-quality shipping product (Store-first) creates the economic base. Public narrative stays honest about what ships vs. what is research/hardware vision. Respect comes from consistency with the values, not from claims.

## Procedure

1. Ground in current repo reality: read `memory/vision.md`, `memory/user.md` (Tauchfliege status), `docs/dev/FOUNDER_PRODUCT_LAW.md`, `docs/dev/ECHOEL_VISION_2026-10-19.md`.
2. Score the proposal: Does it advance one of the four pillars (Entspannung/access, Frieden/transparency, Umweltschutz/sustainability, Inklusion) without violating red lines?
3. Propose the smallest reversible next step that keeps the system homogeneous.
4. If public-facing, draft only what is true today; label future vision clearly as concept/research.
5. Log material alignments to `inspiration.csv` or `decisions.csv` as appropriate.

## Output style

Compact, measured, with ⛔ warnings where needed. Lead with what already works. Name the exact files. Suggest the next concrete action that serves both product shipping and the larger vision.
