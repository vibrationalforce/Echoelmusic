Security and privacy lens, round 1. There are no earlier reviews to reconcile: the job folder holds only board.json and spec.md. The diff does not touch .claude/, any CLAUDE.md or .claude/rules/. All four security minors from the job-008 round-1 review are fixed in this diff:
(1) An oversized foreign file was read whole at launch. begin() now reads only the last 2 x capacity + 64 bytes through FileHandle seek/readToEnd (DiagnosticLog.swift:62, 133-140). Memory and main-thread I/O at launch are bounded, even when someone puts a huge file at the exported path through Files or Finder (UIFileSharingEnabled + LSSupportsOpeningDocumentsInPlace, project.yml:85-86). Under the app's own writes the file is at most 2 x capacity + 17 bytes, so the tail always holds the whole own file.
(2) NSError domains were written unfiltered. DiagnosticLog.domain (lines 184-189) keeps ASCII letters, digits and . - _ per Character, keeps the last 64, and maps everything else to _. A domain can therefore no longer forge a newline, a run header or arbitrary text. The test with a newline and spaces in the domain matches the code.
(3) Carry-over keyed on a marker line. It now keys on line shape (isOwn, lines 164-173: timestamp shape, then a character, no Cc scalars), so free text a user added in Files no longer moves into the next shared file.
(4) failed() sent localizedDescription to os_log as .public. It now uses .private (AudioEngine.swift:160). The step() mirror stays .public, but it carries only StaticString text and numbers.
The atomic Data.write replaces the path rather than following it, so the write cannot escape the Diagnostics folder. The path is fixed, outside both App Groups, excluded from backup and never synced. No new required-reason API is used: FileHandle seekToEnd/readToEnd is not on Apple's list. text() still reads the whole file, but it has no production caller (git grep finds only the tests). Moving StoreController() after beginApp() (EchoelStudioApp.swift:38) changes only ordering inside init and opens no new exposure.

Findings:
- **minor** `EchoelStudio/Core/Sources/EchoelCore/DiagnosticLog.swift:150` — The privacy claims go further than the shape check. The ownLines doc says "Anything else — a line someone added in Files … stays behind" (lines 150-151). The type doc says "So nothing a musician typed … reaches the file through this type" (lines 14-15). Spec A4 says such a line "erreicht so nie die nächste geteilte Datei". isOwn (lines 164-173) checks only the 26-byte timestamp shape and the absence of Cc scalars. So a line someone types in Files as "2026-10-23T01:15:00.000Z  My Secret Song" passes and is rewritten into the next file under the run-before header. testOnlyTheLogsOwnLinesAreCarriedOver uses only a line without a timestamp, so it does not test this case. The risk is low: the user wrote that text into this file themselves. But the sentence is absolute, and it is the one a later session or the privacy text will quote.
  - Fix: Narrow the wording at lines 14-15 and 150-151, and in A4, to "a line that is not in this log's shape does not move on". Optionally add a test assertion that documents the limit, for example that a timestamp-shaped foreign line is carried.
- **minor** `EchoelStudio/Core/Sources/EchoelCore/DiagnosticLog.swift:62` — The new expression `2 * capacity + 64` overflows and traps if the public init is given capacity > (Int.max - 64) / 2, for example Int.max meant as "unlimited". That would crash at the first line of App.init, on every launch. Before this diff, capacity was only subtracted and passed to suffix, so it could not overflow. Today the only caller (Diagnostics.swift:8) uses the 256 KiB default, so the case is not reachable.
  - Fix: Clamp capacity in init (for example `Swift.min(Swift.max(1024, capacity), 64 * 1024 * 1024)`), or compute the tail length with `multipliedReportingOverflow` and saturate.
