1. **major** `.claude/skills/factory/SKILL.md:93` — Step 6 says `.claude/**`, `scripts/**`, `scratchpads/**` and `docs/**` mean 'kein Lauf'. For docs/** that is false, and docs/** is the public website. `.github/workflows/auto-merge-docs.yml` runs on every claude/** push that touches docs/**. When `git diff origin/main..<sha>` is docs-only it cherry-picks the commit to main, and `pages.yml` ('Deploy Website', on main, paths docs/**) then publishes it. The factory order is build = push (table, SKILL:28; 'dann Commit', :53-56), then review. So a docs-only website slice goes live BEFORE the claims lens reads it. If instead the job folder under scratchpads/ is in the same delta, docs_only becomes false and the website change never reaches main by automation, which the skill does not say either. This is exactly the class the factory exists for: 'eine Behauptung nach außen' (:119) and 'die Prüfrunde NACH dem Commit' (:125-126). A smaller instance of the same problem: `scripts/check-infoplist.sh` is in the path filter of `Xcode Compile Check`, so 'scripts/** = kein Lauf' is not fully true either.
   - Vorschlag: In step 6, name docs/** separately: 'Website: kein Gate, aber auto-merge-docs.yml + Deploy Website veröffentlichen eine reine docs-Delta'. In step 3, say that a docs/ (and ContentPipeline/ or fastlane/metadata) slice is reviewed on the LOCAL commit before the push. The lenses read local git, so this works. Then say how an approved docs slice reaches main. Drop scripts/** from the no-run list, or name the one exception.
