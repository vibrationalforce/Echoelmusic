## Befunde

1. **minor** · `EchoelStudio/Core/Sources/EchoelCore/ProjectLibrary.swift`:184
   - Befund: In the two-step case-only rename, the code decides whether the rollback worked with `files.fileExists(atPath: url.path)`. That asks whether something exists at the old name, not whether the package came back. On a case-insensitive volume (the APFS default) the target and the old name are the same name. So step 2 fails mainly when another item took that name between the two moves. The only concurrent creator is the earlier-songs import, which reserves package folders off the main thread with createDirectory (DocumentController.reservePackage). In that case the rollback also fails, but fileExists(url) is true because the other item is there now. rename throws a plain error instead of RenameStranded, and DocumentController.followRenamedSong (line 639) calls moveFailed(error, fileNow: url, moved: false) and leaves currentURL on the old path. The next saveNow then writes this song's project.json into the imported song's package, while this song's Media stays under the in-between name. That is the second-package-without-audio outcome that round-1 m3 was meant to close. It needs a reservation with the same name inside the microseconds between two renames, during the one-time earlier-songs import, so the risk is low.
   - Vorschlag: Ask about the package, not the old name: if `between` still exists after the failed rollback (`files.fileExists(atPath: between.path)`), throw RenameStranded(url: between, underlying: error); otherwise throw the error. That holds whatever has taken the old name since.
