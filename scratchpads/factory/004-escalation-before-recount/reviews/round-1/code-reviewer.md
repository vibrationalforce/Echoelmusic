2. **major** `.claude/workflows/echoel-factory-review.js`:276 — The widened `garbled` class (C1, U+2028/9, bidi controls, zero-width, BOM) is justified by the comment at line 274-275: git prints none of these unquoted when core.quotePath=false. That is false. I measured it in a scratch repo: committed files named a⟨U+202E⟩b.py, e⟨U+200B⟩f.py and c\u0085d.py are printed raw by `git -c core.quotePath=false diff --name-only`. Only the C0 name (g\tz.py) is quoted. So a real file with such a character makes every lens return the name it copied correctly, and line 277 returns RERUN on every call. That return happens before lockChanged is computed (line 293). A range that edits .claude/settings.json and also adds such a file therefore RERUNs forever and never escalates. Probed: RERUN for code-reviewer, security-agent and ux. The base class [\x00-\x1f\x7f] only matched characters git always quotes, so it could never loop on a real name. This diff adds a deterministic RERUN ahead of the fixed lock escalation, which goes against the job's own Goal and Assumption: a RERUN re-calls a round, and nothing holds the head still.
   - Vorschlag: Compute the lock and judge sets before the garbled return and escalate on a lock change first. Or treat a name that every lens reports identically as real and ESCALATE it (a Trojan-Source name is a founder or security matter), keeping RERUN only for a name that one lens alone reports. Correct the comment and add a selftest case: a real bidi name plus a lock change from every lens → ESCALATE.
