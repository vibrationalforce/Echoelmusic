## Zusammenfassung

Security lens, round 1 (no earlier reviews). The diff is factory tooling only: no app code, no secrets, no network or on-device data paths. The ASCII fence (non-ASCII escaped, every '--' broken, one line) holds up. Reading the lock list with `git show <base>:` is an improvement, and the hard-coded lock-config escalation now fails closed against fabricated or partial lens lists, because the lens lists are united. One major remains, and it hits the job's own Goal ("a job cannot soften its own check"): the deterministic escalation lives in the workflow file, which is not locked. The harness runs that file from the working tree, so a job that edits it is judged by the edited copy. This round proves it: the prompt I received asks for `changedFiles`, which occurs 0 times in the base version. The `.claude/hooks/` half of that escalation is the only deterministic line for hook files written through Bash: `protect-founder-gated.py` says itself that `.claude/hooks/` is not protected, and `permissions.ask` covers only the Edit tool. Guard claim 8 does not pin it. The minors are gaps in the privacy and legal file list, lens-supplied file names placed unfenced into the approver prompt, a founder-record check that only matches a file name, a review without a `changedFiles` list that skips the lock check silently, and a `base` the caller can move.

## Befunde

1. **major** `.claude/workflows/echoel-factory-review.js`:188 — The judge itself is not locked. `LOCK_CONFIG` / `isLockConfig` (lines 188-189) covers `.claude/settings.json`, `.mcp.json` and `.claude/hooks/`. The workflow file is not in that set, and neither are its selftest and its guard. The harness runs the workflow from the working tree, so a job that edits it is judged by its own edit. That job could, in the same diff, delete `|| f.startsWith('.claude/hooks/')`, point the approver back at the working tree, or relax the counting, and still get APPROVE. This round shows it: base f61d7872d has 0 occurrences of `changedFiles`, yet this lens prompt asks for them, so job 003 is being reviewed by its own head version. The hooks half matters most. `protect-founder-gated.py` LIMITS says `.claude/hooks/` is not protected by the hook (`PROTECTED_DIRS = ()`), and `permissions.ask` `Edit(/.claude/hooks/**)` covers only the Edit and Write tools. A hook edited through Bash is therefore caught only by this escalation. Guard claim 8 (`TheFactoryReviewersAreReadOnlyTests.swift:196`) compares only the hook's `PROTECTED_FILES` with `LOCK_CONFIG`, so nothing pins the hooks prefix either. The Goal's "cannot soften its own check" and "always escalates" fail against the most direct way to soften the check.
   - Vorschlag: Add a deterministic self-edit rule next to lockChanged. A change to `.claude/workflows/echoel-factory-review.js`, `scripts/factory-review-selftest.py` or `Tests/CISmoke/TheFactoryReviewersAreReadOnlyTests.swift` should ESCALATE like a lock-config change. At minimum, the approver must diff the workflow against `${a.base}` and escalate any rule that was removed or loosened. Extend claim 8 to parse the `Edit(/…)` entries in `permissions.ask` of `.claude/settings.json`, so that `.claude/hooks/**` must also escalate under `isLockConfig`. This makes job 003 itself escalate, which matches GM27 still being open in `docs/dev/FOUNDER_INBOX.md:146`.
2. **minor** `.claude/workflows/echoel-factory-review.js`:191 — `SENSITIVE` misses privacy and legal files that exist in the repo. The regex matches only the flat `docs/(privacy|terms|…).html` names. It misses the redirect stubs `docs/privacy/index.html` and `docs/terms/index.html`; changing their `location.replace` target re-points the policy link, and `fastlane/metadata/*/privacy_url.txt` carries the extensionless `https://echoelmusic.com/privacy`. It also misses `THIRD_PARTY_NOTICES.md` (licence text, see inbox LR2) and `docs/_headers` (Permissions-Policy `camera=(), microphone=()` and the CSP). A job that changes any of these outside `paths` lists them only in `outsideScope`, never in `sensitiveOutside` or `scopeOpen`, so Assumption 6 is only partly delivered.
   - Vorschlag: Widen the list to `/^docs\/(privacy|terms|health|impressum|security|claims)(\.html|\/index\.html)$/`, `/^THIRD_PARTY_NOTICES\.md$/` and `/^docs\/_headers$/`, and add one selftest case for a directory-form page.
3. **minor** `.claude/workflows/echoel-factory-review.js`:276 — `lockChanged.join(', ')` places file names reported by the lenses into the approver prompt OUTSIDE the escaped fence. `isLockConfig` admits any string that starts with `.claude/hooks/`, so a `changedFiles` entry with newlines and instructions reaches the approver as unfenced text. The decision is already forced to ESCALATE, so this cannot produce an APPROVE, but it can steer the founder-facing `forTheHuman` and acceptance text.
   - Vorschlag: Before use, drop or reject any `changedFiles` entry outside a path charset (no whitespace or control characters, e.g. `/^[A-Za-z0-9._\/@+-]+$/`), or pass the names through the same escaping as `fenced`.
4. **minor** `.claude/workflows/echoel-factory-review.js`:328 — `citesRecord` passes any evidence string that mentions `FOUNDER_INBOX`, including an unanswered row. The selftest's example record (`scripts/factory-review-selftest.py:162`, 'docs/dev/FOUNDER_INBOX.md GM27' leading to APPROVE) is an open question in the real inbox (`docs/dev/FOUNDER_INBOX.md:146`, "[ ] offen"). The deterministic gate on founder decisions therefore reduces to dropping a file name.
   - Vorschlag: Change the selftest example to an answered row. Make the approver prompt require citing the row's answer and its date. Optionally require a row id plus an `[x]` or a date pattern in the evidence.
5. **minor** `.claude/workflows/echoel-factory-review.js`:224 — When a review comes back without a `changedFiles` array, `lists[i]` is null, and that review counts neither as blind nor as missing. If every lens answers without one, `changed` is empty and the INVALID check (`lists.some(l => l !== null)`) is skipped. `lockChanged` is then `[]`, so the deterministic lock escalation is skipped silently and the round goes on to the approver. Schema enforcement in the harness makes this unlikely, but the workflow does not fail closed on it.
   - Vorschlag: Treat a non-null review whose `changedFiles` is not an array as RERUN, like `blind`, and add a selftest case for it.
6. **minor** `.claude/workflows/echoel-factory-review.js`:292 — "Locked at the job base" is only as good as the `base` the caller passes. Nothing checks `a.base` against the job's recorded base. A later round given a base after a lock-config commit moves that commit out of `range`, and with it out of both `lockChanged` and the approver's view.
   - Vorschlag: Have the approver confirm that `git show ${head}:${jobDir}/board.json` records `base` equal to `${a.base}`, and escalate on a mismatch.
