## Befunde

1. **major** `.claude/workflows/echoel-factory-review.js`:201 — With rename detection on (the git default; confirmed on 1118a1bd3), `git diff --name-only <range>` lists only the DESTINATION of a renamed file. A job that runs `git mv .claude/hooks/protect-founder-gated.py scripts/x.py` or `git mv .claude/settings.json .claude/settings.json.off` reports only the new path in changedFiles. So lockChanged (line 240) is empty, the deterministic ESCALATE of AC2 and the Goal ("eine Änderung an der Sperr-Konfiguration eskaliert immer") is bypassed, and the approver's check against the same unscoped list (line 294) misses it as well. The same hole drops a renamed-away docs/privacy.html from sensitiveOutside.
   - Vorschlag: Ask for `git diff --name-only --no-renames ${range}` in the lens prompt (line 201) and the approver prompt (line 294). A rename then appears as a deletion of the source plus an addition of the destination. Update the selftest needle (factory-review-selftest.py line 111) and add a case that feeds a renamed-away lock file.
2. **major** `scripts/factory-board.py`:46 — `str(s.get("reviewedBy", "")).strip()` turns a present-but-null reviewedBy into the string "None", which counts as reviewed (false and 0 do the same). Probed: a done job with scopeOpen [{"file":"LICENSE","reviewedBy":null}] vanishes from --open. That is a fail-open in exactly the rule AC7 adds. It contradicts SKILL.md ("ohne reviewedBy (oder mit leerem) ist offen") and the sibling device_open, where a null verified stays open. null is the natural placeholder for the template key `reviewedBy`.
   - Vorschlag: Count an entry as reviewed only if reviewedBy is a non-empty string: `r = s.get("reviewedBy"); open if not (isinstance(r, str) and r.strip())`. In load() (line 80), report a non-string, non-null reviewedBy as a problem. Add a null case to the selftest.
3. **minor** `.claude/workflows/echoel-factory-review.js`:185 — inScope does not normalise the way git pathspecs do. PATH (line 169) admits `.` and `./scripts`, which git treats as the repo root and `scripts`. inScope compares them literally, so paths ['.'] or ['./scripts'] put every file outside scope (INVALID) or mislabel in-scope files as outsideScope. This contradicts the comment "a path matches itself and everything below it". The hook's is_protected strips './' for this reason.
   - Vorschlag: Strip a leading './' and treat '.' as matching everything, or reject both in PATH.
4. **minor** `.claude/workflows/echoel-factory-review.js`:228 — `lists.some(l => l !== null) && !changed.length` returns INVALID ("the call is wrong") when ONE lens answered with an empty list and the others are MISSING. That case is a miscount plus missing reviews, which should be RERUN. The spec says INVALID only when the list is empty for every lens.
   - Vorschlag: Return INVALID only when every lens answered (`lists.every(l => l !== null)`) and the union is empty. Otherwise fall through to the blind or missing RERUN.
5. **minor** `.claude/workflows/echoel-factory-review.js`:191 — SENSITIVE matches only `docs/<name>.html`, but `docs/privacy/index.html` and `docs/terms/index.html` exist.
