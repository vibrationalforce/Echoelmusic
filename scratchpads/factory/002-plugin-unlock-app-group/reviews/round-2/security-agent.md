## Befunde

1. **minor** `EchoelStudio/App/Store/StoreController.swift:23` — Init now starts the Transaction.updates listener and a separate launch Task that calls refreshOwned (lines 23-29). These are two unordered refreshOwned passes on the MainActor, and they interleave at every `for await` suspension. The last one to finish writes PluginUnlock.recordOwned, and that may be the OLDER pass. Failure case: at launch, the updates stream delivers a revocation (a refund made while the app was closed), so the listener's pass writes false. The launch pass began enumerating currentEntitlements before the revocation landed, finishes later, and writes true. The extension then stays unlocked until the next launch pass (PluginLicense.swift:9 returns before StoreKit). The reverse, a stale false, heals itself through the extension's StoreKit fallback. Before this diff the first pass ran in series ahead of the listener, so this ordering is new. load/buy/restore already overlapped with the listener, so the bug class is not new.
   - Vorschlag: Give refreshOwned a generation counter: increment a MainActor `passID` at entry, and write isOwned and recordOwned only if the counter is unchanged at exit. Alternatively, serialise the passes through one stored Task, awaiting the previous pass before starting a new one.
