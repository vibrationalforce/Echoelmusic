## Findings

- **minor** `docs/privacy.html:102` — The privacy page has a section on what Echoel Studio does with data (lines 102-110), but it does not mention the new local file. The file stores when the app was active or in the background, plus the audio interface's channel counts and sample rate, in Files → Echoel → Diagnostics. Nothing on the page becomes false: the 'do not store … session duration / hardware specifications' list sits under the earlier-app section (line 112). But a musician deciding whether to email the file cannot learn what it holds from the policy. The spec puts website text out of scope, and that is acceptable because no sentence turns false.
  - Fix: In a later docs slice, add one bullet to the Studio list, for example: 'Diagnostics: a text file in Files → Echoel → Diagnostics records the app's audio steps and when it was opened, with no song, track or file names. It leaves the device only if you share it.'
- **minor** `EchoelStudio/App/Documents/Diagnostics.swift:10` — The Goal ('the musician can share a text file in Files under Echoel → Diagnostics') can only be reached if someone tells the musician the file exists. This diff adds no in-app pointer, and no tester-facing text (EchoelStudio/RELEASE, support page) names the path. A2 and the out-of-scope section defer this on purpose because the WIP limit is full, so this records the gap; it does not ask for a new surface.
  - Fix: When the device ask from A2 is filed, put the exact path 'Files → On My iPhone → Echoel → Diagnostics → Echoel diagnostics.log' into the TestFlight notes or the FOUNDER_INBOX device family. Testers then know what to share after a crash or a silent start.
- **minor** `EchoelStudio/Core/Sources/EchoelCore/DiagnosticLog.swift:19` — Once the app has ended, '== this run ==' is misleading. A musician who opens Files right after a crash, without relaunching Echoel, shares the crashed run under 'this run'. A developer reading the file days later sees 'this run' for a launch that is long over. Times are UTC (the 'Z' suffix) with no hint for someone who reports 'it cut out around 9 pm' in local time. The timestamps settle the order, so this is wording only.
  - Fix: Consider '== latest run ==' (with '== run before ==') and a launch line that says the times are UTC. Tests should go on referring to the constants, not the literal text.
