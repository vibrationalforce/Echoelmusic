## 1. Existing projects and products

### Takeaway
"Agent drives the DAW" exists today almost entirely as open-source MCP bridges for desktop DAWs (Ableton, REAPER, Bitwig, Logic) plus two late-2025 research systems (DAWZY on REAPER, Sony's LLM2Fx-Tools); shipped commercial "AI" in DAWs is still either single-purpose DSP assistants (iZotope, Logic Mastering Assistant) or documentation chatbots (FL Studio Gopher) that do not take actions.

### Cited Findings
**Open-source MCP bridges (OSS)**
- ahujasid/ableton-mcp: ~3.2k stars, 437 forks, MIT, 73 commits. Architecture = Ableton MIDI Remote Script running a socket server inside Live + Python MCP server; protocol is JSON over TCP (`type` + `params` → `status` + `result`/`message`); version handshake via `get_remote_script_info`. No undo mechanism documented — only advice to "save your work before extensive experimentation". Stated limits: complex arrangements must be split into smaller steps, designed for Ableton's default devices/browser items, timeouts occur, only one client at a time. Telemetry on by default; prompt/MIDI dataset recording opt-in. — [GitHub ahujasid/ableton-mcp](https://github.com/ahujasid/ableton-mcp)
- Other Ableton bridges differ by transport: adindotdev/ableton-mcp (Node, MCP stdio ↔ OSC/UDP via AbletonOSC remote script); Simon-Kansara/ableton-live-mcp-server (OSC, MIT); uisato/ableton-mcp-extended; opendining AbletonLiveMCP lets Claude send arbitrary Python strings executed inside Live's embedded interpreter (maximum power, minimum safety). — [Glama adindotdev](https://glama.ai/mcp/servers/@adindotdev/ableton-mcp), [Simon-Kansara](https://github.com/Simon-Kansara/ableton-live-mcp-server), [uisato](https://glama.ai/mcp/servers/uisato/ableton-mcp-extended), [opendining](https://glama.ai/mcp/servers/opendining/ableton-mcp-server)
- REAPER: TwelveTake-Studios reaper-mcp exposes 129 tools (mixing, mastering, MIDI), MIT, ~15 stars; shiehn/total-reaper-mcp uses a Lua bridge + Python MCP over file IPC and offers "tool profiles" because many LLM APIs cap tool counts (e.g. 128 for OpenAI/Groq). — [Glama total-reaper-mcp](https://glama.ai/mcp/servers/shiehn/total-reaper-mcp), [TwelveTake listing](https://enterprisedna.co/directories/mcp/twelvetake-studios-reaper-mcp)
- Logic Pro: one MCP server claims 35 tools via AppleScript + Accessibility API + virtual MIDI; another uses Mackie Control over MIDI + Accessibility and states Logic is "the least scriptable major DAW" with no AppleScript API — the two contradict each other. — [Glama logic-pro-mcp (rubenknol)](https://glama.ai/mcp/servers/rubenknol/logic-pro-mcp), [Glama Logic Pro MCP](https://glama.ai/mcp/servers/meo5uninsk)
- Bitwig: an MIT MCP server controls transport, mixer, device remote controls; a separate DAW-MCP project reads/edits MIDI clips in Bitwig and Ableton via DAW extensions. — [LobeHub MCP DAW search](https://lobehub.com/mcp?q=daw)

**Research systems (PAPER)**
- DAWZY (arXiv 2512.03289, Dec 2025; NeurIPS workshop 4-pager): open-source assistant turning text, voice or humming into reversible REAPER edits. GPT-5 interprets intent, calls MCP tools and generates Lua ReaScript; actions are "grounded in live project state", state is refreshed before mutation, safety via atomic scripts + undo. Open-source baselines (e.g. Qwen3-Coder) "frequently produced invalid indices" when full track/parameter mappings were not considered. MOS study, n=21: Enjoyment 4.48, Learning 4.38, Collaboration 4.29, Usability 4.14 (Control score cut off in snippet); all above neutral 3. — [arXiv abs](https://arxiv.org/abs/2512.03289), [OpenReview PDF](https://openreview.net/pdf?id=GUgut5mO52)
- LLM2Fx-Tools (arXiv 2512.01559, Sony AI + KAIST, ICLR 2026 poster): multimodal tool-calling LLM that listens to audio, selects effect types, orders them and estimates parameters with chain-of-thought; infers Fx-chain + parameters from dry/wet audio pairs, validated on style transfer; LLM-as-judge rates reasoning appropriate. Releases LP-Fx, an instruction dataset with CoT + tool-call annotations. — [ICLR 2026 poster](https://iclr.cc/virtual/2026/poster/10009732), [Sony AI](https://www.ai.sony/publications/LLM2Fx-Tools-Tool-Calling-For-Music-Post-Production/)
- LLM2Fx predecessor (arXiv 2505.20770, 2025): zero-shot text → EQ/reverb parameters; reports LLM parameter generation beats prior optimization approaches; uses in-context DSP features, DSP function code and few-shot examples. — [arXiv 2505.20770](https://arxiv.org/abs/2505.20770)
- Loop Copilot (arXiv 2310.12404, QMUL/Yamaha/MBZUAI): LLM orchestrator selecting backend generative models per task over multi-round dialogue; keeps "essential musical attributes" in a shared global attribute table for coherence across edits; evaluated by interviews/questionnaires; follow-up thesis user study n=8 (3 starters, 3 intermediate, 2 experts); admits it cannot do fine-grained edits (→ MusicMagus). — [arXiv html v2](https://arxiv.org/html/2310.12404v2), [thesis-related arXiv 2411.12641](https://arxiv.org/pdf/2411.12641)
- WavCraft (arXiv 2403.09527, ICLR 2024 LLM-Agents workshop): audio analysis module captions input → LLM "audio programmer" decomposes the task and writes a program calling expert models/DSP functions (generation + editing such as infill/removal). — [arXiv 2403.09527](https://arxiv.org/html/2403.09527v3)
- ComposerX (arXiv 2404.18081): multi-agent GPT-4 framework for symbolic composition; claims multi-agent setup significantly improves GPT-4 composition quality. — [arXiv 2404.18081](https://arxiv.org/pdf/2404.18081)

**Commercial (SHIPPED)**
- FL Studio 2025 "Gopher" (beta since Aug 2024 invite-only, shipped mid-2025 as free update): chatbot trained on FL manual + production knowledge, answers questions in-app; Q&A, not actions. — [AlternativeTo, Jul 2025](https://alternativeto.net/news/2025/7/fl-studio-2025-introduces-gopher-an-ai-powered-assistant-for-answering-all-your-questions/), [Attack Magazine](https://www.attackmagazine.com/news/fl-studio-2025-adds-ai-support-and-workflow-improvements-in-annual-update/)
- iZotope (Native Instruments) Ozone 12 / Neutron 5: Master Assistant (since 2017 lineage) now "customizable flow"; Neutron Mix Assistant; vocal-balance via "Vocal Checker"; Sound On Sound reviewed Ozone 12 in Dec 2025. Analysis → preset/target-match, not conversational. — [NI bundle page](https://www.native-instruments.com/en/products/izotope/mix-and-master-bundle-standard), [Sound On Sound](https://www.soundonsound.com/node/4934322)
- Logic Pro 11 (May 2024): Session Players (bass/keys, extending Drummer), Mastering Assistant (since 10.8), Stem Splitter, ChromaGlow; one reviewer notes the players are symbolic, not generative-LLM. No LLM/agent control found. — [Apple/BusinessWire](https://www.businesswire.com/news/home/20240507524533/en/Logic-Pro-takes-music-making-to-the-next-level-with-new-AI-features), [Audiofanzine review](https://en.audiofanzine.com/general-sequencer/apple/logix-pro-11/editorial/reviews/testing-apple-logic-pro-11.html)

### Inferences
- No major DAW vendor ships an action-taking LLM agent as of the sources found; the action layer is community MCP glue. An integrated, typed, undoable agent inside the app (Echoelmusic's direction) is ahead of the shipped market, not behind it.
- The three bridge transports (fixed JSON command set, OSC, arbitrary code exec) form a power/safety spectrum; DAWZY and opendining sit at the "generate code" end, which needs a frontier model; a typed command enum is the end that small models can drive.

### Gaps
- Could not verify: LANDR, Waves, Sonible, Splice, Bitwig native AI-agent features (no reliable 2025–26 sources surfaced in searches run). MusicAgent (Microsoft Muzic) and SongComposer not retrieved. No GitHub star/activity data verified except ableton-mcp.
- DAWZY's per-task success rates: an aggregator claims "100% GPT-5 vs 25–50% open-source", unverified against the paper — treat as unconfirmed.

## 2. Tool-call design: granularity, undo/transactions, safety, grounding, latency

### Takeaway
What works: a small, typed, schema-validated tool set grounded by an explicit state snapshot read before every mutation, all mutations atomic and undoable; low-level `set_parameter` is reliable only when the model is given the exact ID/index map, while "make the chorus bigger" style intents work best as a planner step that compiles into those typed calls.

### Cited Findings
- DAWZY's failure mode for weaker models is grounding, not intent: invalid track/parameter indices when the full mapping is not in context; its fixes are refresh-state-before-mutation, atomic scripts, undo. — [arXiv 2512.03289](https://arxiv.org/abs/2512.03289)
- ableton-mcp: complex arrangement requests must be split into smaller steps; timeouts occur; no undo, user told to save first. — [GitHub](https://github.com/ahujasid/ableton-mcp)
- Tool-count pressure is real: REAPER MCP needs "tool profiles" because APIs cap at 128 tools; TwelveTake exposes 129. — [Glama total-reaper-mcp](https://glama.ai/mcp/servers/shiehn/total-reaper-mcp)
- Loop Copilot keeps cross-turn consistency through a shared structured attribute table rather than relying on chat history. — [arXiv 2310.12404v2](https://arxiv.org/html/2310.12404v2)
- High-level semantic → parameter mapping (e.g. "warmer", "more space") is the LLM2Fx line: LLM predicts EQ/reverb parameters, and with audio input (LLM2Fx-Tools) chooses and orders effects with CoT before emitting tool calls. — [arXiv 2505.20770](https://arxiv.org/abs/2505.20770), [ICLR poster](https://iclr.cc/virtual/2026/poster/10009732)
- Apple's guidance for its on-device model: max 3–5 tools per request, one-phrase descriptions; if the model should always have some information, run the tool yourself and put the output in the prompt instead of offering a tool; split argument-generation and result-processing across two sessions when near the limit. — [Apple TN3193](https://developer.apple.com/tutorials/data/documentation/technotes/tn3193-managing-the-on-device-foundation-model-s-context-window.md)
- CHI 2024 prior work (Louie et al., cited in search summary) found steering tools increase users' sense of control, trust and understanding of generative music AI. — [Search summary referencing CHI 2024 PDF](https://iris.unito.it/retrieve/fd062785-090c-4058-8098-17427854af31/2024-CHI.pdf) (indirect; not read)

### Inferences (applied to Echoelmusic)
- Two-tier tool surface fits both the evidence and the existing code: (a) low-level `ParameterToolCore.set` with normalized 0–1 values and registry-validated keyPaths (the model never sees raw ranges, so clamping is free); (b) the typed `EchoelCommand` enum as the mid-level action set (relative dB, duplicate part, compose here). A "make the chorus bigger" request = planner turn that emits a short list of (b)/(a) calls, previewed and applied as ONE undo step.
- Grounding: inject `describeState` output (compact: selected track, its parameter keyPaths with current normalized values) directly into the prompt rather than as a tool — this is exactly Apple's "run the tool directly" advice and DAWZY's refresh-before-mutate rule. `ParameterToolCore.list(query:)` as a search tool keeps the inventory out of the context window.
- Transactions: batch all agent writes from one user turn into a single `.agent` undo transaction (`agent.undoLast` already exists as a command ID); show a diff ("Track 2 level −3 dB → −6 dB") before commit for anything structural (duplicate/delete/compose); parameter nudges can apply live with one-tap revert.
- Safety: no tool that executes code or deletes; destructive ops require confirmation; never write from the audio thread — the ParameterToolCore header already routes through a control-plane apply closure.
- Latency: agent actions are not real-time; keep them off any bio/audio path and treat them as seconds-scale edits.

### Gaps
- No published latency measurements for any DAW agent were found.
- No controlled comparison of low-level vs high-level tool granularity in music specifically.

## 3. Evaluation and user studies: do producers want it, which tasks work

### Takeaway
Evidence is thin and mostly small-n/self-report: users rate human-in-the-loop DAW assistants positively (DAWZY MOS 4.1–4.5, n=21), producers adopt AI most for utility tasks (stem separation, restoration, mix/master assistants), and the recurring condition for acceptance is retained creative control; no benchmark yet scores agents executing mix moves.

### Cited Findings
- DAWZY MOS n=21: Enjoyment 4.48, Learning 4.38, Collaboration 4.29, Usability 4.14; objective eval = four reproducible tasks (incl. multi-instruction FX processing, workflow automation), success rates reportedly not quantified per a third-party summary. — [OpenReview PDF](https://openreview.net/pdf?id=GUgut5mO52), [EmergentMind](https://www.emergentmind.com/papers/2512.03289)
- MixAssist (arXiv 2507.06329, Univ. of Utah, Jul 2025): 431 audio-grounded conversational turns from 7 expert–amateur sessions with 12 producers; fine-tuned Qwen-Audio clearly beat other models at helpful, context-aware mixing advice (LLM-as-judge + human experts). Authors frame the gap: most AI mixing research targets full automation rather than collaborative instruction. — [arXiv 2507.06329](https://arxiv.org/abs/2507.06329), [Zenodo data](https://zenodo.org/records/15848443)
- Adoption surveys conflict by sampling: Soundplate ~20%, Tracklib ~25% of producers use AI; Tracklib: ~¾ of AI users use it for stem separation, nearly half for mastering/EQ in plugins; LANDR (own user base) reportedly 87%; a Sonarworks-linked 2025 chart (n=1,194): audio restoration 58%, mixing assistants 38%, mastering services 33.9%; "would never use AI" fell from 29% (2023) to 18% (2025); respondents prioritise creative control. — [RouteNote](https://routenote.com/blog/artificial-music-20-25-of-music-producers-use-ai/), [Sonarworks](https://www.sonarworks.com/blog/research/ai-music-production-2025) (page not directly readable; figures from search snippet), [Hypebot](https://www.hypebot.com/?p=74474)
- Grounded-theory study of 30 independent musicians: four agency modes (tool-assisted, human-led co-creation, hybrid authorship, AI-dominant); musicians judge output by whether it "sounds like me". — [JAM (TCI-Thaijo)](https://so02.tci-thaijo.org/index.php/jam/article/view/288549)
- UW 10-week case study (n=9 novice undergrads): Human-AI Co-Creation Stage Model; "collaging and refinement" of multiple AI outputs. — [arXiv 2501.15276](https://arxiv.org/html/2501.15276v2)
- Loop Copilot user study n=8; limitation: no fine-grained editing. — [arXiv 2310.12404v2](https://arxiv.org/html/2310.12404v2)

### Inferences
- Tasks that score well: explanation/teaching (MixAssist, Gopher), FX/parameter suggestion from a descriptor (LLM2Fx), workflow automation (DAWZY). Weak: fine-grained musical editing (Loop Copilot), long arrangement edits (ableton-mcp must split them), anything requiring exact IDs without grounding.
- For Echoelmusic the "co-producer that explains and nudges, user keeps the hand on the fader" pattern matches the evidence better than autonomous mixing.

### Gaps
- No CHI 2025/2026 paper specifically on agentic DAW control by professional producers was found; no study measured whether producers keep using such agents over weeks.

## 4. Model options: cloud vs on-device

### Takeaway
Apple's on-device model (~3B, 2-bit QAT, 4096-token window incl. tool schemas, 3–5 tools recommended) is free, offline and private and is adequate for a narrow typed-command router over a pre-grounded state snapshot; open-ended "co-producer" planning with large state and many tools has so far only been shown reliable with frontier cloud models (GPT-5 in DAWZY), with open small models failing on index grounding.

### Cited Findings
- Apple on-device model ≈3B parameters, 2-bit quantization-aware training, KV-cache sharing; server model is a PT-MoE on Private Cloud Compute; framework provides constrained tool calling, guided generation, LoRA adapters. — [Apple tech report 2025, arXiv 2507.13575](https://arxiv.org/abs/2507.13575v2), [Apple ML research](https://machinelearning.apple.com/research/apple-intelligence-foundation-language-models)
- Context window 4096 tokens per `LanguageModelSession`; instructions, prompts, tool schemas/inputs/outputs, Generable schemas and responses all count; ~3–4 chars per token in Latin languages; `tokenCount(for:)` (iOS 26.4, TN3193 updated 2026-03-31); overflow throws `.exceededContextWindowSize`; prompts 1–3 paragraphs; 3–5 tools max; Foundation Models Instruments template for profiling. — [Apple TN3193](https://developer.apple.com/tutorials/data/documentation/technotes/tn3193-managing-the-on-device-foundation-model-s-context-window.md), [InfoQ Mar 2026](https://infoq.com/news/2026/03/apple-foundation-models-context)
- Apple docs: for more reasoning/context use Private Cloud Compute or a server model provider; third-party guides claim PCC gives 32K (not confirmed in Apple docs). — [Apple FoundationModels docs](https://developer.apple.com/documentation/foundationmodels.md), [blakecrosley.com](https://blakecrosley.com/es/blog/apple-foundation-models-framework)
- Developer reports: model is scoped to summarise/classify/extract/short rewrite/structured output, not open reasoning; safety guardrails produce many false positives; silent model updates can change behaviour; unavailable on ineligible devices / Apple Intelligence off / while downloading. — [natashatherobot.com](https://www.natashatherobot.com/p/apple-foundation-models), [atelier-socle.com](https://www.atelier-socle.com/en/articles/foundation-models-api-guide)
- MLX Swift (`mlx-swift-lm`) supports local inference, streaming, tool calling, LoRA; Qwen3-1.7B 4-bit is a common default; guidance: 8 GB iPhones (15 Pro+) for larger models, stay under ~60% of RAM, simulator cannot reproduce Metal perf. No verified iPhone tok/s numbers found. — [tessl mlx-swift reference](https://tessl.io/registry/dpearson2699/swift-ios-skills/3.9.0/files/skills/apple-on-device-ai/references/mlx-swift.md), [Apple MLX M5 post (Mac)](https://machinelearning.apple.com/research/exploring-llms-mlx-m5)
- Open models underperform on DAW grounding (DAWZY: Qwen3-Coder invalid indices). — [arXiv 2512.03289](https://arxiv.org/abs/2512.03289)

### Inferences (applied to Echoelmusic)
- Budget check: 4096 tokens ≈ 12–16 KB text total. A compact state (≤ ~30 parameters as `keyPath=0.42` lines) + 3–5 short tools + Generable plan schema fits; the full registry inventory does not — hence search-tool or pre-filter by selected track.
- Recommended tiering: Tier 1 on-device Foundation Models for intent → typed `EchoelCommand`/`@Generable` plan (guided generation guarantees schema-valid output, which removes the "invalid index" class if IDs are enums/validated keyPaths). Tier 2 optional cloud (Claude/GPT/Gemini, opt-in, explicit consent) for multi-step planning or explanation; send only the textual state snapshot, never bio data — biometric frames should stay on-device by default (consistent with the repo's egress-policy stance). Tier 3 MLX/llama.cpp adds app-size and RAM cost (hundreds of MB to GBs of weights) for little gain over the system model; only worth it for devices without Apple Intelligence.
- Cost: on-device = zero marginal cost; cloud = per-token billing plus a server/key-management obligation, which conflicts with the repo's current "zero external deps / no backend" posture.
- Fresh session per call (current `FoundationModelsBrain`) is the right default under a 4K window; carry continuity via the state snapshot, not transcript.

### Gaps
- No measured tool-calling accuracy for Apple's on-device model on any benchmark found; no iPhone tok/s or time-to-first-token figures verified; PCC third-party developer access terms not confirmed.
- No cloud pricing gathered for this note (out of scope; check current provider price pages before planning).
